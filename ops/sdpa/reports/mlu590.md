## 2. 实现选择

### 2.1 不可用路径（实测）

| 尝试 | 结果 |
|---|---|
| `aten::_scaled_dot_product_efficient_attention` | MLUFallback 到 CPU 后 `NotImplementedError` |
| flash / cudnn private attention | 无 MLU 实现，落到 CPU 即失败 |
| Python `F.sdpa` 作为 backend 内部调用 | A1 注册 `AutogradPrivateUse1` 后经 dispatcher 递归（同 p800 教训） |
| FlagGems `_cambricon` Triton attention | 精度全过（265/265），但比原生慢 **10-40x**（1k D64: 8.4ms vs 0.31ms） |

### 2.2 最终实现

- **主路径**: 直调 `aten::_scaled_dot_product_attention_math`——与 MLU 原生
  `F.sdpa` 相同的 matmul+softmax 复合，非递归，实测 **0.12-0.52x** 原生
  （比 FlagGems 快约 5-10x）。
- **bool mask**: 转 additive `-inf` bias（math kernel 直接收 bool 在本栈
  误差 ~0.19，additive 后与参考一致）。
- **causal+mask 并存**: 先折叠进 mask 再调 math（与 `_native_shim` 同策略；
  MLU `F.sdpa` 亦拒绝二者并存）。
- **全遮蔽行**: 输出端 `masked_fill` 恢复 CPU/aten 的 NaN 语义。
- **可微直调**: q/k/v/mask `requires_grad` 时复用 A1 数学 backward
  （`_SDPA_A1_Function`），FlagGems/math private 无完整 autograd。
- **兜底**: math private 不可用时走 FlagGems；再不可用走 fp32 reference。

## 3. A1 注册

| 项 | 结论 |
|---|---|
| dispatch key | `AutogradPrivateUse1`（与 torch_npu 同；`AutogradMLU`/`MLU` 亦可命中） |
| register 守卫 | 放宽为 torch_npu **或** torch_mlu 可用 |
| autograd | 统一数学 backward；dq/dk/dv 与原生子进程对照 max_err ≤ 6.1e-5 |
| direct autograd | 包装 A1 Function（FlagGems 无 autograd；math private 不可依赖） |
| 拦截 | op 层 count>0；注册路径与直调路径逐位一致；framework 拦截 28 次 |

kernel 级调度/融合，不是语义分叉（op 层与原生逐位一致）。FlagGems Triton
在本栈显著更慢，仅作对照与兜底。

## 6. 关键平台发现

1. MLU 私有 efficient/flash/cudnn attention 均不可用（CPU fallback 失败）；
   唯一可用非递归 private 入口是 `_scaled_dot_product_attention_math`。
2. math private 对 **bool mask** 在本栈误处理（err≈0.19），必须先转
   additive bias；`F.sdpa`/reference 对 bool 正确。
3. FlagGems `_cambricon` attention 精度过黄金但比原生慢 10-40x，
   且无 autograd——不可作生产主路径。
4. A1 注册 key 为 `AutogradPrivateUse1`（与 torch_npu 一致）；
   `AutogradMLU`/`MLU` 注册也能命中，但 PrivateUse1 是 torch_mlu 后端 key。
5. 全遮蔽行 math private 返回有限值，需显式恢复 NaN（同 p800 教训 #3）。
